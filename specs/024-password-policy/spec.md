# Feature Specification: 密碼複雜度政策（管理員可設定、系統驗證就緒）

**Feature Branch**: `024-password-policy`

**Created**: 2026-07-01

**Status**: Draft

**Input**: Phase 0 brainstorm — `docs/superpowers/024-password-policy.md`（密碼複雜度政策由管理員在系統設定頁調整；「密碼政策 ＋ 個人中心」2 刀組的第 1 刀・政策先行；完整 7 項；提供純驗證原語、於本刀 dormant、由刀2 個人中心改密碼接線）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理員設定密碼複雜度政策 (Priority: P1)

系統管理員想規範全站可接受的密碼形態。管理員進入系統設定頁，看到一組密碼複雜度政策項——兩個長度數值（最小、最大）與五個開關（需含大寫、需含小寫、需含數字、需含特殊符號、禁止密碼與帳號相同），逐項調整成組織想要的規則，設定即被保存。

**Why this priority**: 這是本刀對使用者可見的核心價值與 MVP——沒有它，管理員無從設定密碼規則。政策的「可設定與持久保存」是後續一切（改密碼時套用）的基礎。

**Independent Test**: 於系統設定頁調整最小長度並切換某個開關，重新載入該頁，驗證顯示的值為剛才所設（代表已保存於伺服端、非僅前端暫存）。

**Acceptance Scenarios**:

1. **Given** 管理員在系統設定頁, **When** 檢視設定, **Then** 看到 7 項密碼政策（2 個長度數值＋5 個開關）各附說明文字。
2. **Given** 管理員看到某個開關型政策, **When** 切換開／關, **Then** 該設定即時保存、重新載入後維持新狀態。
3. **Given** 管理員看到最小長度欄, **When** 輸入合法正整數並確認, **Then** 該值被保存、重新載入後維持。

---

### User Story 2 - 系統拒絕不合法的政策數值 (Priority: P2)

管理員在設定長度政策時可能誤填非數字、零、負數或過大的值。系統必須明確拒絕這類輸入、不讓無意義的政策值靜默生效。

**Why this priority**: 保護政策資料的完整性；若長度被設成無效值而靜默保存，日後套用政策時會行為錯亂。建立於 P1 之上，是設定面的守門。

**Independent Test**: 嘗試把最小長度存為非數字／零／負數／超出容許上限，驗證系統以明確的業務錯誤拒絕、且原值保持不變。

**Acceptance Scenarios**:

1. **Given** 管理員編輯最小或最大長度, **When** 送出非數字／零／負數／超過容許上限的值, **Then** 以業務驗證錯誤拒絕、不寫入、保留原值、呈現清楚的錯誤訊息。
2. **Given** 管理員編輯某開關型政策, **When** 送出「開／關」以外的值, **Then** 同樣以業務驗證錯誤拒絕、不寫入。

---

### User Story 3 - 系統能判定密碼是否符合政策（供後續改密碼套用） (Priority: P3)

在管理員設定好政策後，系統需要一個「就緒」的能力：給定一個候選密碼與當前政策，判定它是否符合，並在不符時一次列出所有未滿足的條件。本刀先建立並完整驗證此判定能力，尚未接到任何實際設定／變更密碼的流程（該接線屬後續個人中心功能）。

**Why this priority**: 這是政策的最終用途基礎。將「判定能力」與「實際 enforce」分離，可先獨立、可靠地驗證判定正確性，降低後續改密碼功能的風險。屬能力就緒、非本刀使用者直接操作，故列 P3。

**Independent Test**: 對「一組已設定政策」與「一個候選密碼」求值，驗證判定結果正確，且不符時一次回報所有未滿足條件（非遇第一項就停）。

**Acceptance Scenarios**:

1. **Given** 政策要求最小長度 8 且需含特殊符號, **When** 以候選密碼 `abc`（過短且無特殊符號）求值, **Then** 判定為不符、且同時回報「長度不足」與「缺特殊符號」兩項。
2. **Given** 政策啟用「禁止密碼與帳號相同」, **When** 候選密碼等於帳號（不分大小寫）, **Then** 判定為不符、回報「與帳號相同」。
3. **Given** 候選密碼滿足所有已啟用的政策條件, **When** 求值, **Then** 判定為符合、無違規項。

---

### Edge Cases

- **政策項缺失**：某密碼政策項不存在（尚未建立或被移除）→ 求值時該項採保守預設（長度用內建預設、開關視為關），判定不因缺項而報錯。
- **最小長度 ＞ 最大長度（管理員誤設）**：系統仍逐項獨立驗證與保存（前端輕量防呆提示）；求值時因無密碼能同時滿足上下界，一律判定不符，不當機、不靜默放行。
- **多位元組字元**：密碼含非 ASCII 字元 → 長度以「字元數」計，非位元組數。
- **邊界長度**：密碼長度剛好等於最小或最大 → 視為符合（含邊界）。
- **空／全空白密碼**：依長度與字元類別條件正常判定（通常判不符）。
- **政策全關（預設狀態）**：所有字元類別要求與「禁止同帳號」皆關、長度為預設 → 僅長度條件生效。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理員 MUST 能在系統設定頁檢視全部密碼複雜度政策項，且每項附有可理解的說明。
- **FR-002**: 系統 MUST 提供下列 7 項可設定政策：最小長度、最大長度（數值型）；需含大寫字母、需含小寫字母、需含數字、需含特殊符號、禁止密碼與帳號相同（開／關型）。
- **FR-003**: 管理員 MUST 能調整任一政策項；變更 MUST 被持久保存，並於重新載入後反映最新值。
- **FR-004**: 長度類政策 MUST 僅接受合法正整數且落在容許範圍內；非數字／零／負數／超界 MUST 以業務驗證錯誤被拒絕、不寫入、保留原值。
- **FR-005**: 開關類政策 MUST 僅接受「開／關」兩種值；其他值 MUST 以業務驗證錯誤被拒絕。
- **FR-006**: 系統 MUST 能就「一組已設定政策」判定「一個候選密碼」是否符合，並在不符時回報**所有**未滿足的條件（非短路、非只回第一項）。
- **FR-007**: 「密碼是否含特殊符號」之判定 MUST 有明確定義的字元界定（確切界定於 planning 定案）。
- **FR-008**: 「禁止密碼與帳號相同」之判定 MUST 為不分大小寫的相等比較。
- **FR-009**: 長度判定 MUST 以字元數（非位元組數）計，且邊界值（等於最小或最大）視為符合。
- **FR-010**: 當某政策項未設定（缺項）時，系統 MUST 以保守預設求值（長度用內建預設、開關視為關），MUST NOT 因缺項而報錯。
- **FR-011**: 密碼政策之檢視與設定 MUST 僅限具系統管理權限者（沿用既有系統設定頁之權限，不放寬）。
- **FR-012**: 本刀之密碼符合性判定能力 MUST 就緒且經完整測試，但 MUST NOT 在本刀被接入任何實際設定／變更密碼的流程（該接線屬後續個人中心功能）。
- **FR-013**: 政策項之預設值 MUST 保守：長度採合理預設、所有字元類別要求與「禁止同帳號」預設為「關」，使導入本刀不改變既有登入行為（零回歸）。
- **FR-014**: 本刀 MUST NOT 變更資料庫結構（僅新增政策資料列），且 MUST NOT 影響既有系統設定項（如既有 session 開關）之運作。

### Key Entities

- **密碼複雜度政策（Password complexity policy）**：一組決定「可接受密碼」的規則——最小長度、最大長度、是否需各字元類別（大寫／小寫／數字／特殊符號）、是否禁止與帳號相同。以系統設定的鍵值列呈現。
- **政策違規（Policy violation）**：某候選密碼未滿足的單一政策條件（如長度不足、超過上限、缺特殊符號、與帳號相同）；一次判定可回報多個違規。
- **系統設定項（System setting）**：既有的鍵值設定單元（鍵、值、值型別、說明）；密碼政策為其新增之資料列，值型別區分「數值」與「開／關列舉」。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理員在系統設定頁可見全部 7 項密碼政策並成功調整（2 個數值＋5 個開關），變更於重新載入後 100% 保留（畫面顯示與伺服端儲存一致）。
- **SC-002**: 對長度政策送出非數字／零／負數／超界值，100% 被以明確業務錯誤拒絕，且原值不變。
- **SC-003**: 密碼符合性判定對「涵蓋每一政策項的測試案例」100% 給出正確結果，且不符時列出**全部**未滿足條件。
- **SC-004**: 政策項缺失時採保守預設求值、不報錯（以「缺項」案例驗證通過）。
- **SC-005**: 導入本刀後，既有系統設定項（session 開關）與既有登入行為零回歸，且資料庫結構無變更。
- **SC-006**: 新增之政策資料列為可逆——可乾淨移除、回復至導入前狀態。

## Assumptions

- 密碼政策沿用既有「系統設定」機制儲存與存取（鍵值列表），**不另建資料表、不新增對外端點、不新增權限規則**。
- 政策項預設值：最小長度＝8、最大長度＝64、所有字元類別要求與「禁止同帳號」＝關（保守、導入不改既有登入行為）。長度容許範圍上限於 `/speckit-plan` 定案（brainstorm 暫定 1..1024）。
- 「特殊符號」之確切字元界定於 `/speckit-plan` 定案（brainstorm 暫定：非英數字元）。
- 最小長度 ＞ 最大長度屬管理員誤設：前端輕量防呆＋後端各欄獨立驗證；求值時視為「無密碼可符合」（不當機、不靜默放行）；跨欄硬性驗證延後（非本刀）。
- 密碼符合性判定於本刀為「就緒待接」：完整測試但不接任何實際密碼設定流程；實際 enforce（改密碼時套政策）屬後續 025 個人中心。
- 政策項說明沿用既有系統設定之做法（隨資料列提供其說明），與既有 session 設定項一致；**不新增介面翻譯鍵**。
- 後端不新增 workspace crate。

## Dependencies

- 既有「系統設定」功能（008）：鍵值儲存、讀取／更新流程、系統管理權限（super-only）、同交易稽核紀錄。
- 既有系統設定頁：現以開關呈現列舉型設定、對非列舉型僅唯讀顯示——本刀需擴充其對「數值型」設定的可編輯控件。
- 既有業務驗證錯誤通道（wire `2222`／既有 i18n 錯誤鍵）作為「不合法政策值」的拒絕載體（復用既有系統設定 invalidValue 錯誤，不新增鍵）。
- 既有密碼雜湊／驗證工具（不變更）；本刀僅新增「複雜度判定」純邏輯，與雜湊機制無耦合。
- 既有稽核與治理不變式：資料存取單一管道（facade）、稽核欄成對、端點守恆檢查——本刀零新端點、零 schema、預期無 constitution amendment（於 `/speckit-plan` Constitution Check 確認）。
