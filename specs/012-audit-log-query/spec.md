## Clarifications

### Session 2026-06-19

- Q: 審計中心的版面——三類日誌（操作異動／API 存取／登入嘗試）如何呈現？ → A: **單頁三分頁**——側欄一個「審計中心」入口，頁內以三個分頁切換三類日誌；非三個獨立側欄頁。
- Q: 每筆紀錄的「操作者」如何顯示？ → A: **顯示操作者名稱**（非僅內部識別碼）；操作者**即使後來被刪除仍顯示其名稱**（審計正確性）；系統發起（無操作者）顯示為空。
- Q: 篩選方式（逐欄）？ → A: **逐欄 fuzzy/exact**——文字/IP/路徑/帳號/地區/資料表等欄位**部分比對（模糊）**、操作類型/方法/成敗等有限集**精確（下拉）**、時間**範圍（起訖）**；操作者支援**按名稱模糊搜尋**。
- Q: 來源 IP 要不要拆成 client_ip（HTTP 直連）／xff_ip（X-Forwarded-For）／real_ip（解析或 Cloudflare header）三欄統一模型？ → A: **延後（讀端先行）**——本刀讀**現有** schema 的既有 IP 欄（操作異動有單一來源 IP；存取/登入有「已解析來源 IP」+「原始 X-Forwarded-For」）；三欄統一 forensic 模型＋寫入端擷取（含 Cloudflare）＝**後續刀**（動既有日誌表結構與寫入基建）。
- Q: 「誰把某使用者的角色由 A 改成 B」要不要在審計內容中呈現？ → A: **延後**——審計頁如實呈現現有稽核內容；使用者角色集的前後差異目前未存入稽核快照，補強屬未來寫入端增強，不在本刀（角色×選單之異動已可審）。
- Q: 誰能存取審計查詢？ → A: **僅超級管理員**（稽核敏感）；其他身分（含已認證者）一律被拒。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 超級管理員瀏覽操作異動日誌 (Priority: P1) 🎯 MVP

超級管理員進入「審計中心」，在「操作異動」分頁**分頁瀏覽**全部資料異動紀錄（每列顯示：時間／操作者／操作類型〔新增/修改/軟刪/還原〕／受影響資料表與識別碼／來源 IP）。

**Why this priority**: 「誰改了什麼資料」是稽核的核心問題；此分頁不依賴其他分頁即可獨立交付稽核價值，是本刀最小可交付核心。

**Independent Test**: 以超管開啟審計中心 → 操作異動分頁 → 見分頁列出的異動紀錄；翻頁正常。不依賴存取/登入分頁或進階篩選即可驗證。

**Acceptance Scenarios**:

1. **Given** 超級管理員與既有異動紀錄，**When** 開啟審計中心「操作異動」分頁，**Then** 以分頁列出紀錄（時間／操作者／操作類型／資料表／識別碼／來源 IP），預設依時間新到舊排序。
2. **Given** 紀錄數超過單頁，**When** 切換頁碼/頁大小，**Then** 正確翻頁、總數正確。

---

### User Story 2 - 超級管理員瀏覽 API 存取日誌 (Priority: P2)

超級管理員在「API 存取」分頁分頁瀏覽 API 存取紀錄（時間／操作者／HTTP 方法／路徑／狀態碼／來源 IP／地區）。

**Why this priority**: 「誰存取了哪些 API」用於追查異常存取與越權嘗試；建立在審計中心框架之上。

**Independent Test**: 開「API 存取」分頁 → 見分頁存取紀錄；翻頁正常。

**Acceptance Scenarios**:

1. **Given** 超級管理員與既有存取紀錄，**When** 開啟「API 存取」分頁，**Then** 以分頁列出（時間／操作者／方法／路徑／狀態碼／來源 IP／地區）。

---

### User Story 3 - 超級管理員瀏覽登入嘗試日誌 (Priority: P2)

超級管理員在「登入嘗試」分頁分頁瀏覽登入嘗試紀錄（時間／嘗試帳號／成敗／來源 IP／地區）。

**Why this priority**: 用於偵測暴力破解、可疑登入；是後續登入鎖定（lockout）功能的查詢基礎。

**Independent Test**: 開「登入嘗試」分頁 → 見分頁登入成敗紀錄；翻頁正常。

**Acceptance Scenarios**:

1. **Given** 超級管理員與既有登入嘗試紀錄，**When** 開啟「登入嘗試」分頁，**Then** 以分頁列出（時間／嘗試帳號／成敗／來源 IP／地區）。

---

### User Story 4 - 多維篩選與搜尋 (Priority: P2)

超級管理員要能在各分頁以**多個條件**收斂結果：依時間**範圍**、依操作類型／方法／成敗等**精確**選擇、依路徑／帳號／來源 IP／地區／資料表等**部分比對（模糊）**搜尋，並可**按操作者名稱**模糊搜尋。

**Why this priority**: 大量日誌中定位特定事件（某 IP、某帳號、某時段、某 API）是稽核可用性的關鍵；獨立於基本瀏覽之上。

**Independent Test**: 在任一分頁輸入部分 IP/路徑/帳號 → 結果收斂為含該片段者；選時間範圍 → 僅該時段；未設之條件不影響結果。

**Acceptance Scenarios**:

1. **Given** 某分頁紀錄，**When** 以部分來源 IP（如 `203.0`）搜尋，**Then** 僅回來源 IP 含該片段之紀錄。
2. **Given** 某分頁紀錄，**When** 以操作者名稱片段搜尋，**Then** 僅回該名稱（含片段）之操作者所為之紀錄。
3. **Given** 多個篩選欄位，**When** 僅填部分欄位，**Then** 未填欄位略過、不影響結果（空條件不視為「比對空字串」）。
4. **Given** 設定時間起訖，**When** 查詢，**Then** 僅回該時段紀錄。

---

### User Story 5 - 操作者識別（顯示名稱、含已刪者） (Priority: P2)

每筆紀錄顯示操作者**名稱**而非僅內部識別碼；操作者帳號即使後來被刪除，紀錄仍顯示其當時名稱；系統發起（無操作者）顯示為空/系統。

**Why this priority**: 稽核要能直接讀出「誰」；已刪帳號的歷史行為仍須可追溯——這是審計正確性的要求。

**Independent Test**: 檢視一筆由現存使用者所為的紀錄 → 顯示其名稱；檢視一筆由已刪使用者所為的紀錄 → 仍顯示名稱；系統發起的紀錄 → 操作者欄為空。

**Acceptance Scenarios**:

1. **Given** 由現存使用者所為之紀錄，**When** 檢視，**Then** 顯示該使用者名稱。
2. **Given** 由已刪除使用者所為之紀錄，**When** 檢視，**Then** 仍顯示其名稱（不因刪除而變空）。
3. **Given** 系統發起（無操作者）之紀錄，**When** 檢視，**Then** 操作者欄為空（不誤標為某使用者）。

---

### User Story 6 - 操作異動內容檢視 (Priority: P2)

超級管理員可在「操作異動」分頁**展開**某筆紀錄，檢視該次異動的**前後內容**（before/after），以了解具體改了什麼。

**Why this priority**: 「改成什麼」是稽核的深入需求；建立在操作異動瀏覽之上。

**Independent Test**: 展開一筆修改類紀錄 → 見前後內容；新增類紀錄 → 僅見「之後」內容（之前為空）。

**Acceptance Scenarios**:

1. **Given** 一筆修改類異動紀錄，**When** 展開，**Then** 顯示異動前與異動後內容。
2. **Given** 一筆新增類異動紀錄，**When** 展開，**Then** 「之前」為空、顯示「之後」內容。

---

### User Story 7 - 授權防護（僅超管可稽核） (Priority: P2)

審計查詢為高度敏感：**僅超級管理員**可存取三類日誌查詢與審計中心頁；任何不具權限者（含已登入的其他身分）一律被拒、不洩漏資料；授權一律依**系統當下**角色判定。

**Why this priority**: 日誌含操作者、IP、帳號等敏感資訊；誤放權限風險高，須以對抗式測試驗收。

**Independent Test**: 以非超管呼叫三類日誌查詢 → 被拒（403）；以未認證請求 → 被既有認證守門拒；非超管之側欄不顯示審計中心。

**Acceptance Scenarios**:

1. **Given** 已認證但非超級管理員者，**When** 存取任一日誌查詢，**Then** 回 403 權限不足、不洩漏資料。
2. **Given** 不同角色發起查詢，**When** 判定授權，**Then** 依系統當下角色（非憑證內嵌宣告）。
3. **Given** 未帶/無效憑證，**When** 存取，**Then** 被既有認證守門拒絕。

---

### Edge Cases

- **空條件**：未設定之篩選條件略過、回全部（不得把「未設」當成「比對空字串」而回 0 列）。
- **無匹配**：篩選無命中（含按名搜尋無此操作者）→ 回空頁（非錯誤）。
- **操作者已刪**：操作者帳號軟刪後，其歷史紀錄仍顯示當時名稱（以不過濾軟刪之解析）。
- **系統發起**：無操作者之紀錄，操作者欄為空、按名搜尋不誤含之。
- **時間範圍畸形/僅起或僅訖**：寬鬆處理（僅起＝該時間後、僅訖＝該時間前、畸形＝明確失敗不靜默）。
- **空 payload**：新增類紀錄「之前」為空、軟刪類「之後」可為標記；展開不崩。
- **大量資料**：以分頁與時間範圍控制回傳量，回應在可接受時間內。
- **跨資料表的異動紀錄**：操作異動含對各種資料表（含授權策略）之異動，皆如實顯示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 讓授權者從側欄進入「審計中心」，並於同一頁以分頁切換三類日誌（操作異動／API 存取／登入嘗試）。
- **FR-002**: 系統 MUST 讓授權者**分頁瀏覽操作異動日誌**（時間／操作者／操作類型〔新增/修改/軟刪/還原〕／受影響資料表與識別碼／來源 IP），預設依時間新到舊。
- **FR-003**: 系統 MUST 讓授權者**分頁瀏覽 API 存取日誌**（時間／操作者／方法／路徑／狀態碼／來源 IP／地區）。
- **FR-004**: 系統 MUST 讓授權者**分頁瀏覽登入嘗試日誌**（時間／嘗試帳號／成敗／來源 IP／地區）。
- **FR-005**: 每筆紀錄 MUST 顯示操作者**名稱**而非僅識別碼；操作者**已被刪除仍 MUST 顯示其名稱**；無操作者（系統發起）顯示為空。
- **FR-006**: 操作異動紀錄 MUST 可展開檢視該次異動之**前後內容**（before/after）。
- **FR-007**: 系統 MUST 支援逐欄篩選：文字／IP／路徑／帳號／地區／資料表等欄位**部分比對（模糊）**；操作類型／HTTP 方法／成敗等有限集**精確（下拉）**；時間**範圍（起訖）**；操作者可**按名稱模糊搜尋**。
- **FR-008**: 未設定之篩選條件 MUST 略過（不影響結果）；篩選無命中 MUST 回空結果而非錯誤。
- **FR-009**: 系統 MUST 限**超級管理員**存取三類日誌查詢與審計中心頁；非授權者（含已認證之其他身分）MUST 被拒（403）且回應 MUST NOT 洩漏資料；授權判定 MUST 依系統當下角色、MUST NOT 採信憑證內嵌角色宣告。
- **FR-010**: 本功能 MUST 為**唯讀**——MUST NOT 改動任何日誌資料、MUST NOT **主動**寫入稽核紀錄（查詢不寫操作異動日誌）。〔註：既有 per-request API 存取日誌基建會如常記錄本功能之 GET 請求軌跡，屬基建層既有行為、非本功能之自我稽核，不在本刀變更範圍。〕
- **FR-011**: 顯示之資料 MUST 與來源一致——可為空之欄位（操作者名稱、來源 IP、地區、識別碼、異動內容等）MUST 如實呈現空值、MUST NOT 以誤導之預設值掩蓋。
- **FR-012**: 本功能 MUST NOT 回歸既有登入／身分／權限守門／使用者·選單·角色管理／動態選單查詢行為；為支援本功能所做之資料結構變更（審計頁選單、查詢授權策略、查詢索引）MUST 可逆。

### Key Entities *(資料層一覽；皆既有、本刀只讀)*

| 實體 | 角色 | 說明 |
|---|---|---|
| 操作異動日誌 | 資料異動稽核 | 每次資料異動一筆（操作類型／資料表／識別碼／操作者／來源 IP／前後內容／時間）；append-only、既有基線已建並由前序波次持續寫入；本刀**只讀**。 |
| API 存取日誌 | 存取軌跡 | 每次受認證請求一筆（操作者／方法／路徑／狀態碼／來源 IP／原始轉送標頭／地區／時間）；append-only、既有；本刀只讀。 |
| 登入嘗試日誌 | 登入成敗稽核 | 每次登入嘗試一筆（嘗試帳號／成敗／操作者〔成功時〕／來源 IP／地區／時間）；append-only、既有；本刀只讀。 |
| 操作者（使用者） | 名稱解析來源 | 既有使用者實體；本刀以其識別碼解析顯示名稱（**含已軟刪者**，供審計追溯）。 |

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 授權者可分頁瀏覽三類日誌、且結果與實際資料 100% 一致——由活體＋瀏覽器驗證證實。
- **SC-002**: 多維篩選 100% 正確——部分比對找得到含該片段者、精確選擇不誤含、時間範圍僅回該時段、未設條件略過——由活體＋瀏覽器驗證證實。
- **SC-003**: 操作者名稱解析 100% 正確——現存者顯示名、**已刪者仍顯示名**、系統發起顯示空——由活體驗證證實。
- **SC-004**: 操作異動之前後內容 100% 可檢視——由瀏覽器驗證證實。
- **SC-005**: 非授權存取 100% 被拒（403）且不洩資料；授權 100% 依系統當下角色判定——由活體＋瀏覽器驗證證實。
- **SC-006**: 審計查詢全程**唯讀**——查詢不改動日誌、不**主動**寫稽核（操作異動日誌零新增）；既有 per-request 存取日誌基建照記本功能 GET 之軌跡（基建層既有行為、非自我稽核）——由變更比對＋活體驗證證實。
- **SC-007**: 授權者瀏覽/篩選日誌之回應為即時（一般查詢於數百毫秒內回應、單頁載入 < 1 秒）——由活體驗證證實。
- **SC-008**: 既有登入／身分／權限守門／使用者·選單·角色管理／動態選單行為 100% 零回歸；本功能之資料結構變更可逆（建立後可完整復原）——由活體驗證＋變更比對證實。
- **SC-009**: 審計中心全鏈 100% 實際對後端發出查詢並反映結果（無「假資料」）、訊息在地化——由瀏覽器端到端驗證證實。

## Assumptions

- **既有基礎已就緒、本刀零重建**：三張日誌表（操作異動／API 存取／登入嘗試，含來源 IP／地區／追蹤識別碼／時間欄）、其寫入機制、稽核上下文（操作者／真實來源 IP／地區解析）、認證守門＋授權檢查分層、受治理端點之授權機制、統一回應信封與在地化規約、分頁/篩選讀取規約、使用者名稱解析機制皆已由前序波次建妥；本刀**唯讀消費**之，僅新增審計頁選單項、三條查詢之授權策略與查詢索引（可逆 delta）。
- **單頁三分頁**（Clarifications D1）：審計中心為單一管理頁、三類日誌以分頁切換；側欄一個入口。
- **僅超級管理員**（Clarifications）：三類查詢與審計中心頁限超管；非超管側欄不顯示審計中心、直接呼叫亦被授權守門拒。
- **讀現有 IP 欄、三欄統一 forensic 模型延後**（Clarifications D11）：本刀顯示/篩選現有 schema 之 IP 欄（操作異動：單一來源 IP；存取/登入：已解析來源 IP＋原始轉送標頭）；`client_ip`（HTTP 直連）/`xff_ip`/`real_ip`（解析或 Cloudflare header）三欄統一模型＋寫入端擷取＝**後續刀**（須動既有日誌表結構與寫入基建，宜與真實來源 IP 解析完整化一併處理）。
- **使用者角色變更之稽核內容延後**（Clarifications D4）：操作異動之內容快照如實呈現；使用者「角色集前後差異」目前未存入快照，補強屬未來寫入端增強、不在本刀。
- **日誌保留／清理（retention）out of scope**：日誌無限增長之清理/封存屬另一未排程之決策，不在本刀；本刀僅提供查詢。
- **操作者名稱解析含已軟刪者**：為審計追溯正確性，以識別碼解析名稱時不過濾軟刪（已刪操作者仍顯示其名稱）。
- **唯讀無主動自我稽核**：審計查詢不主動寫稽核（操作異動日誌零新增）；既有 per-request API 存取日誌基建仍如常記錄本功能 GET 之請求軌跡（基建層既有行為、非本功能自我稽核、不在本刀變更範圍）。
- **資料結構變更以可逆方式落地**：審計頁選單、查詢授權策略、查詢索引以可逆之 delta 變更引入（可完整復原），不改動既有日誌表結構。
