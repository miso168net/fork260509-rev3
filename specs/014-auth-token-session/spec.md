# Feature Specification: Auth/Token/Session 合刀（token 輪替鏈＋單一登入生命週期＋硬即時撤銷）

**Feature Branch**: `014-auth-token-session`

**Created**: 2026-06-21

**Status**: Draft

**Input**: User description: "`docs/superpowers/014-auth-token-session.md`（Phase 0 brainstorm spec-design）：把 006 鋪的 Auth 島最小段（login＋授權閘＋會話指標）補成**完整行為島**——token rotation chain（refresh 輪替／雙擊容忍／盜用偵測→撤整鏈→乾淨登出）＋single-session lifecycle（全域 `single_session_default` × 逐使用者 `session_policy` 三態驅動、不符會話→踢）＋硬即時撤銷（停用/刪除 user→撤銷標記→已發 access token 立即失效、不分 single-session 策略）＋過期 token 清理（cleanup-job、dry-run 預設）；並以 **2-instance 多副本驗證**證跨進程收斂與快取失效韌性。四項拍板：C1 多實例＝驗證版／C2 撤銷＝硬即時(fail-OPEN)／C3 逐使用者 `session_policy` 設定 UI＝做／C4 alt-login＝排除本刀。狀態機 states/transitions/invariants/對外碼之權威設計見 `docs/INTEGRATION-DESIGN.md` §4.1（token rotation）/§4.3（single-session）。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登入會話安全輪替與盜用偵測 (Priority: P1) 🎯 MVP

已登入的使用者，其長效憑證（refresh token）**每次使用即輪替**：用它換得新的一對憑證、舊的隨即作廢（單次使用）。若舊的（已用過/已撤銷/不合法的）憑證被**重放**（典型情境：被竊取後攻擊者拿去用），系統**偵測到盜用、撤銷該登入鏈的整條憑證、把使用者乾淨登出**。同時容忍正常的**短時間雙擊**（網路重送同一次 refresh）不誤判為盜用。

**Why this priority**: refresh 憑證遭竊是「長期未經授權存取」的主要攻擊面；輪替（讓憑證單次使用）＋盜用偵測（重放即撤整鏈）是本功能的核心安全價值，**不依賴單一登入或撤銷面即可獨立交付驗證**——是最小可交付核心（MVP）。

**Independent Test**: 拿一個有效 refresh → 換得新對；拿同一個（已輪替成 used 的）refresh 短時間內再送一次 → 容忍（雙擊）；隔一段時間再送或送已撤銷的 → 整鏈撤銷＋乾淨登出。全程不需單一登入/撤銷面即可驗。

**Acceptance Scenarios**:

1. **Given** 一個有效的 refresh 憑證，**When** 使用者（或前端攔截器）以它換新，**Then** 取得新的一對（access＋refresh）、舊 refresh 變為已使用、後續以舊 refresh 換新會被視為重放。
2. **Given** 同一個 refresh 在極短時間內被送兩次（網路重送），**When** 第二次到達，**Then** 視為良性雙擊、發給新對、不撤銷、不報盜用。
3. **Given** 一個已使用（超過容忍窗口）或已撤銷或不合法的 refresh，**When** 被重放，**Then** 系統判定為盜用、撤銷該登入鏈的**整條**憑證、回乾淨登出訊號（非系統錯誤）。
4. **Given** refresh 憑證本身驗章失敗（過期/簽章不符），**When** 送達輪替端，**Then** 回乾淨登出（不誘發前端自動重試迴圈）。

### User Story 2 - 管理員強制單一登入（全域＋逐使用者） (Priority: P1)

管理員能控制「一個帳號是否只允許一個有效會話」：設定**全站預設**（開/關），並可**逐使用者覆寫**（繼承全站／強制開／強制關）。當某使用者的**有效策略為開**時，他在新裝置登入會**踢掉**其先前的會話；**有效策略為關**時，多裝置會話並存。

**Why this priority**: 單一登入是核心安全/合規控制；全站預設＋逐使用者覆寫讓管理員彈性施行。**現況系統其實「永遠踢」**（不論設定為何、新裝置登入即踢舊裝置），與「全站預設為關」的意圖相反——本故事讓設定真正生效。屬核心控制、與 US1 各自獨立可交付。

**Independent Test**: 全站設為開→帳號在 B 裝置登入→A 裝置下個請求被踢（乾淨登出）；全站設為關→A、B 並存不踢；某使用者覆寫為開（全站關時）→該使用者仍單一登入。皆可獨立驗。

**Acceptance Scenarios**:

1. **Given** 某使用者有效單一登入策略為開且已在 A 裝置有會話，**When** 同帳號在 B 裝置登入，**Then** A 裝置下一個受保護請求被踢、乾淨返回登入。
2. **Given** 有效策略為關，**When** 同帳號在多裝置登入，**Then** 各裝置會話並存、互不踢除。
3. **Given** 某使用者 `session_policy` 覆寫為開、而全站預設為關，**When** 該使用者多裝置登入，**Then** 以**逐使用者覆寫**為準（單一登入）、覆寫蓋過全站。
4. **Given** 管理員把全站預設由關切為開，**When** 切換後的請求進來，**Then** 新策略立即生效（無需重啟）、且在所有運行中的實例一致生效。

### User Story 3 - 停用或刪除使用者即時失效其存取 (Priority: P2)

當管理員**停用**或**刪除**某使用者時，該使用者**已發出、尚未過期的存取憑證立即失效**——下一個請求即被拒、乾淨登出，**不分**其單一登入策略、**不需**等到憑證自然過期。使用者被**重新啟用**後，新登入恢復正常。

**Why this priority**: 補上現況安全缺口——目前停用/刪除只擋得住「重新登入」，已發的存取憑證仍可通關到過期（最長約一個憑證效期）。建立在會話機器之上、屬第二優先安全強化。

**Independent Test**: 對一個持有有效存取憑證的使用者執行停用/刪除→其下一個受保護請求立即被拒；重新啟用後新登入可正常存取。可獨立驗。

**Acceptance Scenarios**:

1. **Given** 某使用者持有有效存取憑證，**When** 管理員停用該使用者，**Then** 該憑證在下一個請求即被拒、乾淨登出、不等過期、不分單一登入策略。
2. **Given** 同上，**When** 管理員刪除（軟刪）該使用者，**Then** 同樣立即失效其存取。
3. **Given** 一個曾被停用的使用者被重新啟用，**When** 他重新登入，**Then** 新發的憑證正常通關（撤銷不影響啟用後新發的憑證）。

### User Story 4 - 多副本部署下會話機制跨實例正確 (Priority: P2)

在系統以**多個副本**（水平擴展）運行、共享同一資料儲存時，單一登入施行、策略解析、即時撤銷都能**跨副本一致收斂**：在某副本上改全站策略，其他副本隨即跟上；在某副本登入，其他副本看得到最新會話指標而正確踢人；撤銷在所有副本一致。即使會話熱快取的訂閱**短暫斷線**，機制也能恢復（重新訂閱）。

**Why this priority**: 驗證水平擴展就緒度，是「單機驗不到」的跨實例行為的去風險（設計風險序指定的打樣點）。優先級 P2 因為它建立在核心會話機制之上、是部署面韌性驗證。

**Independent Test**: 起 2 個副本共享同一資料儲存與會話快取；在副本 A 切全站策略→副本 B 隨後生效；A 登入→B 讀到最新指標踢舊會話；中斷會話快取的失效通道→訂閱者恢復重訂閱。可獨立驗（不影響單副本行為）。

**Acceptance Scenarios**:

1. **Given** 2 副本共享儲存且全站策略為關，**When** 在副本 A 把策略切為開，**Then** 副本 B 後續請求以「開」施行（跨進程收斂）。
2. **Given** 2 副本共享會話指標，**When** 使用者在副本 A 登入（有效策略開），**Then** 該使用者送到副本 B 的舊會話請求被踢。
3. **Given** 會話快取的失效通知通道短暫中斷，**When** 通道恢復，**Then** 訂閱者自動重訂閱、後續策略變更仍能收斂（不因一次斷線永久脫鉤）。
4. **Given** 對某使用者執行即時撤銷，**When** 其請求落到任一副本，**Then** 皆被一致拒絕（撤銷標記跨副本共享）。

---

### User Story 5 - 過期會話 token 清理 (Priority: P3)

維運人員能執行一個**清理作業**移除已過期的會話 token：**預設為非破壞性報告**（只計數、不刪）、明確指定執行才**物理移除**已過期者、且**可重複執行**（冪等、再跑結果一致）。

**Why this priority**: 純維護（避免 token 儲存無限成長）；最低優先，因為 token 儲存不在熱路徑、不影響功能正確性。

**Independent Test**: 跑 dry-run→只回報計數、不刪；跑 execute→只刪過期者、保留有效者；再跑一次→冪等（無額外變更）。可獨立驗。

**Acceptance Scenarios**:

1. **Given** 儲存中有已過期與未過期 token，**When** 以預設（dry-run）執行清理，**Then** 只回報將清理的數量、不做任何刪除。
2. **Given** 同上，**When** 以明確執行旗標執行，**Then** 只移除已過期者、未過期者原封不動。
3. **Given** 剛執行過清理，**When** 立刻再跑一次，**Then** 結果一致、無額外副作用（冪等）。

---

### Edge Cases

- **雙擊 vs 盜用界線**：同一 refresh 在容忍窗口內重送＝良性雙擊（發新對、不撤）；超出窗口或對已撤銷/不合法者重放＝盜用（撤整鏈、乾淨登出）。
- **鏈已被撤銷後再用**：會話因單一登入被踢、或因盜用被撤後，其 refresh 再送→乾淨登出（非系統錯誤、不誘發自動重試迴圈）。
- **會話指標讀不到（backing store 抖動）**：附加的會話一致性檢查採**保守放行**（不因熱快取/儲存短暫不可達而誤踢有效會話）。
- **撤銷標記儲存不可達**：即時撤銷的查核採**保守放行**（不讓儲存一抖就鎖死全站；撤銷窗口被短憑證效期兜底）。
- **重新啟用使用者**：撤銷不得阻擋啟用後新發的憑證（以「撤銷時點之前發出的才拒」界定）。
- **全站策略切換的飛行中請求**：切換後新請求即生效（熱載）；切換瞬間的極短窗口可接受、最終收斂。
- **登入永遠更新會話指標**：即使有效策略為關也更新指標，使日後切為開時立即生效（不需重新登入）。
- **同秒多次輪替**：同一使用者極短時間多次輪替不得互撞憑證唯一鍵（以每憑證唯一識別碼確保彼此可區分）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系統 MUST 於每次成功使用 refresh 憑證時**輪替**之——發出新的一對憑證、將原 refresh 標記為已使用（單次使用、單向不可回頭）、新舊同屬一條登入鏈。
- **FR-002**：系統 MUST **偵測 refresh 重放**（已使用超過容忍窗口、已撤銷、或不合法狀態的 refresh 被再次提交）並**撤銷該登入鏈的整條憑證**、回乾淨登出訊號。
- **FR-003**：系統 MUST 容忍同一 refresh 在**短容忍窗口**內的雙擊（網路重送），發給新對而**不**判定為盜用、不撤銷。
- **FR-004**：系統 MUST 由**逐使用者策略**（繼承／強制開／強制關）結合**全站預設**解析出每位使用者的**有效單一登入策略**；「繼承」者跟隨全站預設。
- **FR-005**：系統 MUST 僅在有效策略為**開**時施行單一登入（新登入使該使用者其他有效會話失效、不符的會話於下一個受保護請求被乾淨踢除）；有效策略為**關**時 MUST 允許多會話並存。
- **FR-006**：系統 MUST 允許管理員設定**全站單一登入預設**，並 MUST 允許**逐使用者覆寫**（於使用者編輯面設定繼承/開/關）。
- **FR-007**：系統 MUST 在使用者被**停用或刪除**時**立即撤銷其存取**——其已發出的存取憑證 MUST 於下一個請求即被拒、**不分**單一登入策略、**不需**等待自然過期。
- **FR-008**：系統 MUST 在使用者被**重新啟用**後讓其新登入恢復正常（撤銷 MUST NOT 阻擋撤銷時點之後發出的憑證）。
- **FR-009**：系統 MUST 使管理員對全站單一登入預設的變更**即時生效**於後續施行（無需重啟），並在所有運行中的實例**跨進程收斂一致**。
- **FR-010**：系統 MUST 在以**多副本**共享同一資料儲存運行時，保持單一登入施行、策略解析、即時撤銷**跨副本一致**；會話失效通知通道短暫中斷後 MUST 能恢復（重新訂閱）。
- **FR-011**：系統 MUST 提供移除**已過期**會話 token 的維護作業，**預設非破壞性**（只計數）、僅在明確指定時物理刪除、且**冪等**（可重複安全執行）。
- **FR-012**：系統 MUST 維持前端會話體驗無縫——輪替對使用者透明；被踢或被登出的會話 MUST 乾淨返回登入頁（不白屏、不誘發自動重試迴圈）。
- **FR-013**：系統 MUST 對會話熱快取/撤銷標記儲存的**短暫不可達**保持韌性——backing store 抖動 MUST NOT 造成有效會話的誤鎖（附加查核採保守放行、以短憑證效期兜底）。
- **FR-014**：系統 MUST 保留所有既有行為（登入、使用者資訊、授權、使用者增刪改查、系統設定、稽核）**零回歸**，且 MUST **不需任何資料庫結構變更**（無新表、無欄位變更、無 migration）。

### Key Entities *(include if feature involves data)*

- **會話憑證鏈（rotation chain）**：一次登入產生一條鏈；其下每枚 refresh 憑證有**狀態**（有效／已使用／已撤銷、單向）與**到期時間**；對非有效狀態憑證的重放會撤銷整條鏈。每枚憑證有唯一識別碼以避免同秒輪替撞鍵。
- **單一登入策略**：由**全站預設**（開/關，現為既有系統設定）＋**逐使用者設定**（繼承/開/關，現為使用者既有屬性、預設繼承）組成；解析為每位使用者的**有效開/關**。
- **會話指標（session pointer）**：某使用者當前有效會話的指向；新登入更新之；有效策略為開時，與指標不符的會話即被踢。指標真相持久於資料庫、另有共享熱快取。
- **撤銷標記（revocation marker）**：標示某使用者之存取自某**時點**起被撤銷；該時點之前發出的憑證一律被拒；標記於約一個存取憑證效期後自動到期清除。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：對一組代表性 refresh 情境（正常輪替、容忍窗口內雙擊、重放盜用、不合法憑證）的處置結果與預期相符率 **100%**（新對／容忍／撤整鏈+登出／登出）。
- **SC-002**：被重放的（竊取後再用）refresh 導致該登入鏈**整條撤銷**的比例 **100%**；盜用者藉重放**繼續存取的比例 0%**。
- **SC-003**：有效策略為開時，第二次登入使先前會話於其下一個請求被拒（踢除）的比例 **100%**；有效策略為關時多會話並存、互不踢。
- **SC-004**：被停用/刪除之使用者的既有存取，於**下一個請求週期內**即被拒（非等到憑證效期）的比例 **100%**。
- **SC-005**：管理員對全站單一登入預設的變更，於後續請求**無需重啟即生效**，並在所有運行中實例收斂一致。
- **SC-006**：以 **2 副本**共享儲存運行時，單一登入施行／策略解析／即時撤銷的行為與單副本**一致**（驗證情境中觀察不到跨副本不一致）。
- **SC-007**：清理作業**只移除已過期** token、保留有效者，且重複執行得到**一致終態**（冪等）。
- **SC-008**：每一條踢除/登出路徑都使前端**乾淨返回登入**（無白屏、無自動重試迴圈）——端到端驗證通過。
- **SC-009**：既有功能（登入、授權、使用者管理、系統設定、稽核）**零回歸**；正式環境映像建置成功。
- **SC-010**：本功能**零資料庫結構變更**（無新表、無欄位變更、無 migration）。

## Assumptions

- **schema 已就緒、零 migration**：會話憑證鏈欄（狀態/到期/鏈識別/憑證唯一碼）、逐使用者策略欄（預設繼承）、會話指標欄、全站預設設定，**全部已存在於基線 schema**（波 0 一次全建）；本功能不新增表/欄/migration。
- **建立在 006 之上**：006（Auth 島最小段）已提供 login、授權閘、會話指標寫入、基礎會話一致性檢查（現為「永遠踢」、未讀策略）；本功能在其上把行為島補完整。
- **全域開關走既有設定面**：全站單一登入預設**已是一個系統設定**、可由既有系統設定頁切換；逐使用者覆寫由使用者編輯頁設定。
- **前端已有 refresh 攔截器**：base-web 既有自動 refresh 攔截器，本功能把輪替端點接上、並處理踢除/登出兩通道乾淨返回登入。
- **單副本為預設部署**：多副本僅作**機制驗證**（起 2 實例共享儲存）、非預設拓樸；正式負載平衡與預設多副本留待真水平擴展。
- **授權策略快取的跨實例失效屬後續功能**：本功能只處理**會話端**的跨實例收斂；授權策略（角色權限）快取的跨實例失效是**獨立的後續功能**（治理刀）。
- **替代登入流程不在本功能**：alt-login（其他登入方式）為獨立後續功能、本功能排除。
- **撤銷的儲存可用性權衡**：即時撤銷的查核在撤銷標記儲存不可達時採保守放行（撤銷窗口被短存取憑證效期兜底），以避免儲存抖動造成全站鎖死。
- **明確不在範圍**：替代登入流程（alt-login）為獨立後續功能；正式負載平衡與預設多副本拓樸（本功能只做機制驗證）；授權策略（角色權限）快取的跨實例失效（屬後續治理功能）；任何資料庫結構變更（schema 全在基線）。
